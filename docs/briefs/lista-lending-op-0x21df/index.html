4. Risk Notes

  • After execution any one of the 15 signers of the Safe 0xEEfebb1546d88EA0909435DF6f615084DD3c5Bd8 (threshold 1) can call pause() on each of the four liquidators. While a liquidator is paused, its whenNotPaused entry points revert: on Liquidator and BrokerLiquidator every BOT liquidation, smart-collateral and token-sale function; on V3Liquidator liquidations, V3 share redemption and token sales; on PublicLiquidator the four public liquidation functions (redeemSmartCollateral stays callable there). withdraw functions and admin setters are not gated.
  • unpause() needs MANAGER on each liquidator. At the pin MANAGER is held by the 3-of-6 Safe 0x8d388136d578dCD791D081c6042284CED6d9B0c6 and by Lista's MarketFactory proxy 0xA2ff080D4c0b71B6c8796129DD4aCc0B09D7592c; the batch adds the EmergencySwitchHub. Pausing takes one signature, resuming takes the 3-of-6 Safe or a contract.
  • The EmergencySwitchHub 0xBafB0B5B70A9844Fb9F132ba1C28F888Dd113B34 (Sourcify-verified EmergencySwitchHub) lets its PAUSER call pauseAll / pauseContracts and its MANAGER call unpauseAll and addPausableContracts. Its PAUSER is the same 1-of-15 Safe, its MANAGER the 3-of-6 Safe, and the hub's PAUSER role admin is MANAGER: the 3-of-6 Safe can add hub pausers without this timelock. At the pin none of the four liquidators is in getPausableContracts() (12 entries), so the hub reaches them only after its MANAGER adds them.
  • On the liquidators themselves, PAUSER and MANAGER are administered by DEFAULT_ADMIN_ROLE, which this timelock holds: further grants there still wait the 1-day delay.
  • No initializer runs (upgradeToAndCall with empty data). Each queued implementation only adds OpenZeppelin PausableUpgradeable (ERC-7201 namespaced flag), the PAUSER constant, pause() / unpause() and whenNotPaused on the entry points above; the Sourcify storage layouts are identical, so the proxies start unpaused. The other changed files only add interface declarations.
  • All four queued implementations are Sourcify exact matches (verified 2026-11-17). The batch was scheduled by the 3-of-6 Safe 0x08aE09467ff962aF105c23775B9Bc8EAa175D27F, which is this timelock's proposer, canceller and executor; the executor role is not open to everyone.
