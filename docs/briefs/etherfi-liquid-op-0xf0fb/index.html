4. Risk Notes

  • One scheduleBatch of 5 setManageRoot(address,bytes32) calls (selector 0x21801a99): 2 on the liquidUSD manager, 2 on the liquidETH manager, 1 on the liquidBTC manager. Every call replaces a non-zero root that is live at the pin.
  • A manage root is the Merkle root of the calls a strategist may make through the vault. The leaves of the queued roots are not onchain: what each strategist can do after execution cannot be read from this operation alone.
  • liquidETH: the queued root for 0xc811…23a2 goes to an externally owned account (no code at the pin), so a single key will be able to run every call that root allows.
  • liquidUSD: the root kept for the manager's own address (0x7b57…c13c) is set to zero, so manage calls that the manager contract itself submits can no longer pass Merkle verification.
  • The 4-of-6 Safe 0xcea8…ec96 (Safe 1.3.0) that scheduled the batch is this timelock's proposer, canceller and executor; the executor role is not open, so only that Safe can execute after the ETA or cancel before it.
  • On all three managers owner() is the zero address and each manager's authority lets this timelock call setManageRoot (canCall = true at the pin): execution needs no other approval.
