How to check who can upgrade a DeFi contract

A contract that can be upgraded can be changed by whoever holds the upgrade key. To know who that is you need three facts: is the contract behind a proxy, who is the proxy's admin, and is there a delay between a decision and its effect (a timelock). For any contract on Ethereum or Base, Pacta reads these facts from the chain at a finalized block and returns what the contract exposes in one answer. Where a contract uses its own upgrade code that cannot be read this way, the answer says "not determined" instead of guessing.

Changed 2026-11-28. The example on this page was read from the chain; its newest reading is from 2026-11-15.

Ask it yourself

One line, no key, 100 answers a day free:

Ask with curl
curl -s "https://api.pacta.wtf/v1/check?chain=ethereum&address=0xA35b1B31Ce002FBF2058D22F30f95D405200A15b"

Ask it from an agent

Add the server once:

Add the MCP server
claude mcp add --transport http pacta https://api.pacta.wtf/mcp

Then ask in words: "Who controls 0xA35b1B31Ce002FBF2058D22F30f95D405200A15b on Ethereum?" The agent calls the tool who_controls.

What comes back

The fields of the answer, by their names in the API description:

  • chain, address: the network (ethereum or base) and the contract address checked.
  • block.number, block.hash, block.providers: the block every read was pinned to, its hash, and the two RPC providers that read it.
  • upgradeable, standardProxyDetected: whether a standard proxy slot or upgrade beacon is set: true, false, or null when custom upgrade code cannot be ruled out.
  • controllerType, controllers: each controller found, with its kind, a Safe's threshold and owner count, and a timelock's delay.
  • upgradeDelaySeconds: the minimum delay in seconds when the upgrade admin is a timelock; null otherwise.
  • facts.upgrades, facts.ownerAndRoles, facts.pausing, facts.supply: one plain line each on upgrades, owner and roles, pausing, and supply.
  • isPaused, pauseIndicatorsObserved, mintIndicatorsObserved, canSupplyGrow: whether the contract is paused, and the pause and mint signals found.
  • pending_operations: timelock operations queued for the contract, and when they can run.
  • castCommands: Foundry cast commands that reproduce every read yourself.

One real example

Stader Labs (ETHx): on its sampled timelocked controls, a decided change waits at least 7 days before it runs (read at Ethereum block #26,422,627 on 2026-11-15). The fewest signers needed on any sampled control is 3 of 6 (read at block #26,403,676 on 2026-11-13). Full record: /protocols/stader-labs-ethx/.

What it does not tell you

It tells you who can change the contract and how fast. It does not tell you whether they will, and it is not a rating.

Questions people ask

What is a proxy admin?

A proxy is a contract that passes every call on to a separate implementation contract, so the code behind one address can be replaced. The proxy admin is the account allowed to replace it.

What is a timelock?

A timelock is a contract that holds a decided change for a fixed delay before it can run. While the change waits, anyone can see it.

What if the documents say something else than the chain?

The record shows both: the value read from the chain at a named block and the words of the documents. Where they differ, the protocol is on Protocols whose documents differ from the chain.
