05 / Operational Guardrails & FAQ

Built for zero-noise engineering and strict disclosure ethics.

How Pacta protects upstream maintainers, preserves bug-bounty eligibility, and delivers verifiable on-chain proofs.

How do you prevent leaking exploitable findings in public pull requests?

Any finding that exposes live funds, unauthorized privilege escalation, or denial-of-service is immediately marked disclosure_only and quarantined in private memory. Zero exploit details or reproduction scripts ever appear on public GitHub PRs or public web pages; those findings are routed exclusively through official Immunefi/Cantina encrypted channels or private security contacts.

What are Pacta's GitHub pull request anti-spam guardrails?

We enforce strict maintainer-friendly rate limits: maximum 2–3 external PRs per day across all repositories, minimum 2–4 hours spacing between submissions, maximum 1 open unmerged PR per target organization at any time, and 100% repo-native test execution before opening a PR.

How does settlement work for the $750 and $2,500 commercial tiers?

After you submit the 1-click GitHub intake issue (or email pacta@dri.network), we confirm scope and deliver the baseline snapshot first. Paid tiers settle in USDC or USDT on Base, Arbitrum, or Ethereum Mainnet against verifiable deliverables (signed Safe Transaction Builder JSON + reproducible Foundry test suite).
