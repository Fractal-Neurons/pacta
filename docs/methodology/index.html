Pacta/Methodology

Methodology

One vocabulary for every label on the site: what each status, rosette slice and live-check verdict means.

How it works

  1. Read the docs. Pacta records what each protocol publishes about who can upgrade, pause or change its contracts, and how long changes must wait.
  2. Read the chain at a finalized block. The same controls are read at a finalized block on two independent RPC providers.
  3. Attest the difference on Base. Each result is attested with EAS on Base, so anyone can re-check it later with cast.

Docs vs chain

One status per protocol, used in every table, badge and feed:

Docs-vs-chain statuses
StatusMeaningProtocols
AlignedThe published documentation matches the sampled onchain controls. It says the docs are accurate, not that the protocol is low-risk.122
DeltaDocs and chain differ: the live controls are looser than, or different from, what the protocol documents.55
ProtectiveDocs and chain differ in the safe direction: the live controls are stricter than documented.7
ObservedThe onchain control plane is pinned at a finalized block over RPC; the documentation has not been compared yet.129

Record-level classifications in the JSON feeds map onto the same words: parameter_delta = Delta, protective_delta = Protective, aligned_baseline = Aligned, rpc_observed = Observed. The embeddable badges read "Aligned · Base EAS", "Parameter Delta" or "RPC-Observed" for the same three cases. A protocol is Delta if any of its records is Delta; "Reconciled" marks a Delta that was fixed and re-attested as Aligned.

The control-plane rosette

Five factors, clockwise from the top. Colour, slice length and a letter carry the same information, so the rosette never relies on colour alone; hover or focus a slice to read it.

The live contract check

The live checker reads one contract address at the latest block and gives it a 0–100 heuristic score from its bytecode and storage: who can upgrade or change it, through which controller, and how fast. A Docs-vs-chain status is different: it compares everything a protocol documents about its control plane with every record Pacta has pinned for it, across many contracts. A protocol can be Delta while one of its contracts scores 0, and an Aligned protocol can include a contract a multisig can change. Across the catalog, 55 of the 313 protocols carry at least one adverse docs-vs-chain delta (61 parameter-level deltas across 304 attested checks), and 7 carry protective deltas where the chain is stricter than documented.

The checker on the homepage and /v1/check/preflight read one contract address at the latest block. Its verdict and its 0–100 heuristic score rate that single address, not the whole protocol: a protocol can be Delta while one of its token contracts has no admin at all. Confidence says whether the address is an indexed, verified record or a bytecode heuristic.

Live check verdicts
VerdictMeaning
No standard upgrade or admin authority detectedNeutral. No proxy admin, owner or role with upgrade power was found at this address.

A multisig can change it with no delayWarning. A Safe can change the contract without a waiting period.

Amber is reserved for warnings everywhere on the site. Neutral and good results are never amber.

Evidence and reproducibility

Every record names its block number and block hash, the contract and the call. 304 attested checks are anchored in 36 Base EAS batch attestations; the 129 Observed protocols are pinned over RPC and reproducible with cast, but not attested yet. Machine-readable: scorecards.json, index.json, rpc-pinned.json.

Independence policy

Pacta never sells grades. Payment never alters a Pacta classification. A status changes only when onchain contract state or public documentation changes and is verified at a new finalized block.

Auditor referrals. When code changes are needed, Pacta can refer a team to an independent smart-contract auditor, under a 15% referral partnership with the audit firm. Referrals never influence docs-vs-chain status: a referred protocol is re-read at a finalized block like every other, and its status follows the onchain and documentation evidence only.

Paid verification work for protocol teams funds the engineering; the data, the API and the MCP server stay free for everyone.

Glossary

Control plane
The set of keys, multisigs, timelocks and roles that can change a protocol.
Finalized block
A block the chain will not reorganize; reads pinned to it are reproducible.
EAS
Ethereum Attestation Service: Pacta signs each result onchain on Base.
Timelock
A contract that forces a delay between queuing and executing a change.
x402
An HTTP payment protocol for metered API calls; Pacta's free tier needs no payment.
MCP
Model Context Protocol: how AI agents call Pacta's tools.
